为了把 Analyzer 做成你希望的样子，我需要先确认这些设计决策。
1、你的 Agent 主要面向什么使用场景？
例如：个人效率助手、文档问答助手、代码助手、办公自动化助手、数据分析助手、通用多功能助手。
回答：主要使用场景就是：日常个人使用，比如电脑处理word，excel，pdf等文件（主要是帮我读取这些文件帮助我快速理解文件内容以及常见我想要的文件并将内容写到文件里面），项目设计，开发，测试以及部署软件工程全流程，还可以帮组我管理文件目录文件资源


2、你希望 Analyzer 支持哪些核心意图？
我建议初始意图集合可以包括：calculate、search、summarize、translate、write、analyze、plan、read_file、write_file、execute_code、extract、compare、recommend、chat。
回答：这些意图都需要，除了这些最好是可以多加一些可以支撑问题1中我的日常使用场景的一些核心意图

3、你希望意图名称用中文还是英文？
工程上我建议内部统一用英文枚举，给用户展示时再转中文。
回答：那就内部使用英文，给用户展示的时候再使用中文吧

4、多意图任务最多允许识别几个意图？
例如“搜索资料、总结重点、写成 Markdown 报告”就是 3 个意图。
回答：识别主要意图，最好设置一个意图最多数量，比如可以设置每次对话最多可以实现用户的4个意图（而且还是用户输入内容的最主要的4个，可以给每一个意图一个分数然后去最高的4个，且每个分数都必须大于50分这个阈值可以调整，如果有5个意图，但是只有2个意图分数大于50分，那么就可以认定这2个就是主要意图，另外三个就不是，如果5个都是大于50分，那么就取前面4个意图即可）


5、遇到模糊任务时，你希望 Agent 直接追问，还是先给一个默认方案？
例如用户说“帮我分析一下市场”，是直接问“哪个市场”，还是先给分析框架？
回答：模糊意图那就追问，并且可以引导用户的真实意图，比如列出用户可能真的想问的问题或者实现的目标


6、对高风险领域，你希望策略多严格？
法律、医疗、金融、隐私类任务，是只提示风险，还是禁止直接给结论，只能提供通用信息？
回答：只提示风险

7、是否允许 Analyzer 调用大模型做兜底意图提取？
如果允许，需要确认：大模型只能从固定意图集合选择，还是可以生成新意图？
回答：允许大模型兜底意图提取（但是最好全部都使用前面几层，如果前面几层都提取不出来那就在使用大模型），可以生成新意图，主要还是要根据用户输入的具体内容来，因为固定意图本来就是关键词匹配层的，这个肯定是不全面的

8、分类器训练好之前，当前阶段是否以“规则 + LLM 兜底”为主？
这是我建议的方案，分类器后续作为可插拔增强。
回答：主要以规则+意图分类器为主，LLM作为兜底，比较这个也是会消耗token的，意图分类器模型是在我自己的服务器跑的，LLM需要消耗token

9、你希望复杂度评分严格按七维加权模型实现吗？
也就是完全落地 复杂度判定.md 里的权重：不确定性 3.0、步骤 2.0、风险 1.8、工具 1.5、信息 1.5、数据 1.2、创造性 1.0。
回答：

10、你希望 micro / meso / meso_advanced / macro 四类执行策略保持不变吗？
我建议保留，因为它很适合解释任务型 Agent 的执行层级。
回答：保留吧

11、参数缺失时，Analyzer 要不要输出具体缺失字段？
例如 translate 缺少 target_language，search 缺少 topic，write_file 缺少 file_path。
回答：需要，然后如果会影响用户体验需要给用户进行友好提示或者重试不全参数，日志的话肯定要将具体的错误打印出来

12、你希望 Analyzer 推荐工具吗？
例如识别到 calculate 后推荐 math_calculator，识别到 read_file 后推荐 document_parser。
回答：这个工具的调用不是内部觉得的吗，关用户什么事呢，用户需要的是流畅的得到想要的执行结果，工具的话内部自己进行决策，使用最好的工具（前提是有这个工具，如果没有可以提示用户添加这个工具的mcp或者使用已有工具来实现这个目标，如果所有工具调用方案都缺少某一个工具的话，就提示最好的2个方案缺少哪几个工具，提示用户进行配置）

13、是否需要支持中英文混合输入？
例如“帮我 summarize 这个 pdf”这种输入。
回答：支持中英文混合的输入

14、是否需要 Analyzer 输出可解释原因？
例如“因为命中搜索和总结两个意图，并且包含‘并’，所以判定为多意图 meso 任务”。
回答：可以放到思考部分，就像codex这样每次完成多任务时有正文回答部分，也有思考部分和调用工具执行以及执行结果部分，反正最好是模仿codex的交互方式来显示执行的过程（后续需要有ui界面的所以对话输出交互上可以模仿codex来做）

15、你希望 Analyzer 先做到什么程度算 V1 完成？
我建议 V1 标准是：规则意图识别、多意图识别、实体参数提取、参数缺失判断、风险识别、七维评分、执行路由全部可用。
回答：那就使用你建议的V1标准吧
