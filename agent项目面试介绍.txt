# 灵犀助手（多功能智能任务助手）

## 一、项目一句话定位
这是一个以 Codex 协作为开发工具、按“问答设计-详细设计-步骤设计-开发实现-验收检查”闭环落地的任务型 Agent 项目，核心目标不是聊天，而是把用户需求拆成可规划、可执行、可回放、可验收的结构化任务链路。

## 二、你在面试中可以先讲的主链路
```text
用户输入
  -> Runtime / ReactAgent
  -> Analyzer
  -> Planner
  -> ReActExecutor
  -> Tools / Models / Memory
  -> OutputFeedback / RuntimeResult
```

你可以概括成一句话：
我把 Agent 从“单次模型调用”做成了“可编排、可控、可追踪”的任务执行系统。

## 三、这个项目最主要解决的几个问题
1. 如何让 Agent 先理解任务，而不是直接生成答案。
2. 如何把自然语言拆成结构化计划，避免模型一次性乱输出。
3. 如何让工具调用可控、安全、可追踪。
4. 如何让多轮对话有记忆、能回放、能恢复。
5. 如何让模型、工具、记忆、执行器分层，后续能持续扩展。

## 四、分层设计怎么讲
### 1. Runtime / App 层
负责统一装配、会话管理、CLI/API 接入和运行上下文管理。

你可以这样讲：
我没有把入口层直接写成一个大脚本，而是把 CLI / API 统一收敛到 Runtime，避免每个入口重复实现 Analyzer、Planner、Executor 的主流程。

### 2. Analyzer 层
负责意图识别、参数提取、复杂度判断、风险判断和执行策略路由。

你可以这样讲：
Analyzer 相当于 Agent 的任务理解中枢，它先判断用户到底想做什么、缺什么参数、是否高风险、是否需要澄清或拆步骤。

### 3. Planner 层
把 Analyzer 的结果转成 `TaskPlan / TaskUnit / PlanStep`，形成结构化执行方案。

你可以这样讲：
我没有让模型输出直接变成执行结果，而是先转成 plan，这样做的好处是可控、可测、可追踪，也方便后面做重试和动态重规划。

### 4. ReActExecutor 层
按计划执行 ReAct 循环，负责 `ActionPacket` 校验、Tool / Model / User / Control 调用、Observation 生成、Checker 判定、重试和 fallback。

你可以这样讲：
Executor 不负责理解用户意图，只负责消费结构化计划并执行，它是执行引擎，不是决策大脑。

### 5. Tools 层
提供文件、命令、搜索、翻译、文档解析、MCP 扩展等能力，统一返回 `ToolResult`。

你可以这样讲：
我把工具返回从字符串改成结构化结果，Executor 可以基于 success、error、code 做决策，而不是靠解析文本。

### 6. Models 层
统一模型适配、路由、结构化输出、重试、降级、健康检查和上下文压缩。

你可以这样讲：
我把模型供应商隔离在 ModelManager 后面，让主流程不依赖具体模型实现，后续换模型、做路由和降级都更容易。

### 7. Memory 层
负责会话状态、短期上下文、执行事件、会话回放和自动摘要。

你可以这样讲：
Memory 不是简单聊天历史，而是会话状态和上下文管理层，支持 session 隔离、历史恢复和多轮上下文压缩。

## 五、项目亮点/难点
- 用 Codex 协作完成了完整的工程化开发闭环。
- 做了任务型 Agent 的分层架构，而不是简单的 LLM + 工具脚本。
- 把工具调用、执行事件、最终输出做成结构化协议。
- 做了安全边界控制，尤其是代码执行、文件写入、搜索等高风险能力。
- 支持多模型适配、流式事件输出和会话恢复，工程化味道比较完整。

## 六、面试时常见追问的回答思路
### 1. 为什么要分 Analyzer / Planner / Executor？
因为自然语言输入和真实执行之间存在很大鸿沟。先理解，再规划，再执行，可以把不确定性逐层收敛。

### 2. 为什么要做结构化计划？
结构化计划让任务可控、可测、可回放，也方便做失败重试、步骤级追踪和后续重规划。

### 3. 为什么要统一 ToolResult？
因为字符串返回无法判断成功失败，结构化结果才能让执行器稳定决策。

### 4. 为什么要有 Memory 层？
因为 Agent 不只是单轮问答，还要支持多轮任务、上下文恢复和执行过程回放。

### 5. 为什么要有 Runtime 层？
因为 CLI、API、Session 管理、事件流转发这些入口逻辑不能散落在 Agent 里，统一收口更清晰。

## 七、你可以直接背的一段总结
这个项目不是简单的“模型调用工具”，而是按任务型 Agent 的方式，把系统拆成 Runtime、Analyzer、Planner、ReActExecutor、Tools、Models、Memory 七层。Analyzer 负责理解和路由，Planner 负责结构化拆解，Executor 负责按步骤执行，Tools 负责真实能力，Models 负责统一大脑，Memory 负责会话和回放，Runtime 负责整体编排。这样设计的目标是让 Agent 从 demo 走向工程化，具备可扩展、可测试、可控制和可继续演进的能力。

- 分层架构
- 结构化计划
- ReAct 执行闭环
- 事件流
